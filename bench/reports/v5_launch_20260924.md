## Pilote et corrections de lancement

Le pilote corrigé a terminé : 3 updates de chauffe (76 s, compilation des kernels
incluse), puis 10 updates mesurées. **28,9k tokens/s**, **2267 ms/update**,
**35,37 Go** de VRAM maximale allouée. MFU matriciel indicatif 2,5 % ; ce n’est
pas un bilan complet de tous les FLOPs de cette architecture.
Le benchmark n’active pas TF32 explicitement, contrairement au Trainer ; son
débit n’est donc pas une garantie du débit effectif sur les données.

Trois problèmes ont été rencontrés avant le prétrain :

1. L’image devait installer `wheel==0.45.1` avant causal-conv1d et ajouter
   `/root/app` au `PYTHONPATH` pour importer frlm dans les fonctions Modal.
2. FLA a refusé le backward GDN sous Triton 3.5.1 sur H100 (bug amont #640).
   `tilelang==0.1.14` fournit le backend correctif officiel ; la garde n’est pas désactivée.
3. L’indexeur QSA de référence itérait sur chaque token, même quand tous les
   blocs tiennent dans son budget. `full_context_indexer` retourne alors le masque
   visible, maintient les clés de cache, et conserve le chemin amont au-delà du budget.
   Ce raccourci ne change ni les paramètres ni les noms/formats des poids GGUF.

Un pilote trop lent a été arrêté sans conserver de poids ; seul le run prétrain
contient des mises à jour destinées au modèle final. Crédits consommés affichés
avant ce prétrain : environ 1,23 $ (la facturation peut être retardée).
